# Contribution Guidelines

Thanks for helping. Fixes are as welcome as new entries.

## Dead or moved links

If a link is dead or has moved, [report it](https://github.com/leon-wbr/awesome-canada/issues/new?template=dead-link.yml), or [edit README.md](https://github.com/leon-wbr/awesome-canada/edit/main/README.md) to fix or remove it; GitHub opens the pull request for you. If a project has stopped being maintained but is still useful, move it to [Unmaintained & Archived](README.md#unmaintained--archived) with the year of its last commit.

A weekly check keeps one "Broken links" issue up to date, and a monthly one lists repos that are archived or haven't had a commit in two years. Both are labelled `good first issue`: pick any line and send a fix.

## New entries

Anything useful about Canada can go in: lists, repos, APIs, datasets, sites, tools, communities and podcasts. Before adding one:

- Check it isn't already in the list.
- It should be maintained. Repos should have a commit in the last two years.
- Official government material that only lists services is better added to [wra-sol's Awesome Canada](https://github.com/wra-sol/awesome-canada#readme).

Don't want to open a pull request? [Suggest it in an issue](https://github.com/leon-wbr/awesome-canada/issues/new?template=suggest-entry.yml) instead.

## Format

Add one entry per pull request, in the fitting section, in alphabetical order:

```md
- [Name](https://example.com) - Short description.
```

- The description starts with a capital letter and ends with a period.
- Keep it short and plain: say what it is, not why it's great.
- For an awesome list on GitHub, link to `https://github.com/owner/repo#readme`.

Pull requests are checked with [awesome-lint](https://github.com/sindresorhus/awesome-lint), and new links with [lychee](https://github.com/lycheeverse/lychee). You can run awesome-lint yourself with `npx awesome-lint`.

## Becoming a maintainer

After three merged pull requests, you'll be invited as a collaborator with Triage access, so you can label and close issues. Later, Write access, and you'll be added to `.github/CODEOWNERS` so reviews are requested from you too.
